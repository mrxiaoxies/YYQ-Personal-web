# 个人网站后台管理界面设计

## 1. 背景与目标

当前网站是 Vite + React + TypeScript 单页站点，主要公开内容集中在 `src/App.tsx`。Netlify Functions 已经用于 RAG 问答和访问统计，Netlify Blobs 已经用于保存统计数据。网站还存在一个隐藏的 `#admin` 入口，但目前它只是使用 `VISITOR_ADMIN_TOKEN` 的访问统计面板，不具备账号登录和内容编辑能力。

本次改造为网站增加自建管理员账号和密码登录，并把现有 `#admin` 统一升级为后台管理界面。管理员可以修改 Home、Codex、Showcase、Skills、Resume、Contact 六个栏目，内容保存后立即发布到公开网站，同时保留历史版本和恢复能力。

本期不包含以下内容：

- 季节背景、字体、动效、页面布局和导航结构编辑；
- 静态图片或文件上传；
- RAG 知识库 `knowledge/index.json` 的在线编辑；
- 多角色权限体系；
- 邮件发送服务和邮件找回密码流程；
- GitHub Pages 的后台登录承载。

## 2. 已确认的产品决策

### 2.1 管理员与发布

- 使用自建账号表和密码登录，不使用 Netlify Identity。
- 第一阶段面向单一管理员，但数据结构保留 `role` 字段，便于未来扩展。
- 内容保存即发布，不设置草稿状态。
- 每次保存生成历史版本；恢复历史版本会产生一条新的当前版本记录，不删除旧版本。
- 首次账号通过一次性 `ADMIN_SETUP_TOKEN` 创建。
- 忘记密码通过一次性 `ADMIN_RECOVERY_TOKEN` 重置。

### 2.2 运行位置

- Netlify 主站承载 `/#admin` 的真实登录和管理操作。
- GitHub Pages 继续作为静态公开镜像。
- GitHub Pages 上访问 `#admin` 时显示说明并链接到 Netlify 主站的 `/#admin`，不尝试在跨域页面保存管理 Cookie。
- 两个公开站点都可以读取 Netlify 的公开内容接口，因此动态栏目内容可以同步显示。

## 3. 总体架构

### 3.1 前端

在现有 `App.tsx` 的 hash 路由基础上保留 `#admin`，但把当前 `AnalyticsDashboard` 拆成独立的管理页面组件和请求模块。页面状态分为：

1. 未登录：登录、首次初始化、密码恢复界面；
2. 已登录：后台首页、栏目编辑、历史版本；
3. 会话过期或权限失败：清理本地页面状态并返回登录界面。

管理端沿用网站已有的液态玻璃视觉语言，但使用清晰的后台表单结构。布局需适配桌面和手机端，表单应支持键盘操作、可见标签和可读错误提示。

### 3.2 服务端

建议新增以下 Netlify Function 能力：

- `admin-auth`：初始化、登录、当前会话、退出和密码恢复；
- `site-content`：公开读取当前内容，并提供管理员保存、历史版本和恢复；
- 现有 `analytics`：保留 `/api/visit` 访客写入，将 `/api/stats` 改为使用管理员会话，而不是浏览器提交的固定 token。

所有管理员接口都在服务端完成鉴权和输入校验。浏览器不能直接读写账号、会话、密码哈希或 Blob 内部数据。

### 3.3 Netlify Blobs 数据区

复用现有 Netlify Blobs 能力，但将账号、会话、内容和统计分开存储：

- `yyq-site-admin`：管理员账号、会话、初始化锁和恢复令牌消费记录；
- `yyq-site-content`：当前内容和历史版本；
- `yyq-site-analytics`：现有访问统计数据，保持与管理认证逻辑分离。

Netlify Blobs 中的逻辑记录使用命名空间 key 保存。它不冒充关系型 SQL 数据库；当前单管理员、低写入频率的个人站点场景使用强一致读写即可满足需求。

## 4. 认证设计

### 4.1 管理员记录

逻辑用户记录至少包含：

```text
id
email
emailNormalized
role = admin
passwordHash
passwordSalt
createdAt
updatedAt
active
```

管理员邮箱统一转小写并去除首尾空格。第一期只允许创建一个有效管理员，后续如需增加账号可以基于 `role` 和 `active` 字段扩展。

### 4.2 密码处理

- 使用 Node.js `crypto.scrypt` 生成密码哈希；
- 每个密码使用独立随机盐；
- 使用固定时间比较检查哈希结果；
- 密码长度限制为 12–128 个字符；
- 不在响应、日志、错误信息或 Blob 记录中保存明文密码；
- 初始化和修改密码后不返回密码或哈希数据。

### 4.3 会话 Cookie

登录成功后生成高熵随机会话值，服务端只保存会话值的 SHA-256 哈希。浏览器 Cookie 使用以下属性：

- `HttpOnly`；
- `Secure`；
- `SameSite=Lax`；
- `Path=/`；
- 有效期 7 天。

会话记录包含 `userId`、创建时间、过期时间和最后活动时间。登出、密码重置或会话过期时，服务端删除或拒绝该会话。密码重置后清理该管理员的全部旧会话。

### 4.4 初始化

初始化接口只有在以下条件同时满足时才成功：

- 当前没有已创建管理员；
- 请求提供的 `ADMIN_SETUP_TOKEN` 与服务端环境变量匹配；
- 初始化锁记录尚未消费；
- 邮箱和密码通过格式与长度校验。

成功创建后写入初始化锁。即使后续用户记录被删除，也不能重新打开第一次初始化入口。

### 4.5 密码恢复

恢复接口要求提交管理员邮箱、一次性 `ADMIN_RECOVERY_TOKEN` 和新密码。服务端：

1. 校验令牌是否与当前环境变量匹配；
2. 检查当前令牌指纹是否已经消费；
3. 更新密码哈希；
4. 标记该令牌已消费；
5. 清理所有旧会话。

令牌只以哈希或指纹形式写入 Blob。再次恢复时必须更换 Netlify 环境变量中的令牌。第一期不发送邮件，恢复令牌由管理员通过 Netlify 环境变量临时配置。

### 4.6 防护

- 登录失败使用统一错误提示，不区分邮箱不存在或密码错误；
- 对邮箱和来源进行短时间窗口的失败限流；
- 管理员写入接口校验请求来源，生产环境只允许 Netlify 管理域名和配置的本地开发地址；
- 不记录密码、令牌、Cookie、完整请求体或敏感环境变量；
- 公开接口只返回公开栏目内容，不返回内部 key、版本存储详情或账号数据。

## 5. 内容模型与编辑范围

内容文档包含 schema 版本、更新时间、当前版本 ID 和六个栏目。内容以纯文本为主，列表字段使用数组，链接字段单独存储。

### 5.1 Home

- 小标题；
- 主标题；
- 副标题；
- 两个按钮文字。

按钮行为和目标锚点仍由代码控制，后台只修改按钮显示文字。

### 5.2 Codex

- 栏目小标题、主标题和说明；
- 项目标题、阶段、更新时间、简介；
- 里程碑列表；
- 下一步、公开状态；
- 链接文字和 URL；
- 时间线日期、状态、标题和详情。

项目结构、卡片布局和状态展示样式仍由代码控制。

### 5.3 Showcase

- 栏目小标题、主标题和说明；
- 展示卡片标题和简介；
- 标签文字；
- 下载按钮文字和下载地址。

文件本身仍来自 `public/files/`，后台只修改展示信息和已配置的地址。

### 5.4 Skills

- 栏目小标题、主标题和说明；
- 技能分组标题；
- 每组技能条目。

后台支持分组和条目的新增、删除、排序。

### 5.5 Resume

- 栏目标题；
- 公司名称、任职时间、职位；
- 项目名称、项目时间、项目简介；
- 项目职责要点。

公司、项目和职责均使用可增删排序的列表。

### 5.6 Contact

- 栏目小标题；
- 主标题；
- 联系说明；
- 页面展示用联系方式。

二维码图片、二维码降级图案和联系弹窗行为仍使用现有代码和静态资源。

### 5.7 校验规则

- 所有外部 JSON 请求使用严格字段校验并拒绝未知字段；
- 所有文本作为纯文本渲染，不支持 HTML、脚本或 Markdown 注入；
- URL 只允许 `http://` 和 `https://`；
- 必填标题、简介和列表项不能为空；
- 对单字段、数组长度和总文档大小设置上限；
- 保存前校验状态值、日期格式和链接格式；
- 服务器重新校验前端表单，不能仅依赖浏览器校验。

## 6. 接口契约

### 6.1 认证接口

- `POST /api/admin/auth?action=setup`
- `POST /api/admin/auth?action=login`
- `GET /api/admin/auth?action=me`
- `POST /api/admin/auth?action=logout`
- `POST /api/admin/auth?action=recover`

成功登录和恢复后只返回必要的管理员概要，不返回密码、哈希、令牌或 Blob key。

### 6.2 内容接口

- `GET /api/site-content`：公开读取当前内容；
- `PUT /api/admin/content`：提交完整内容文档和 `expectedVersion`；
- `GET /api/admin/revisions`：读取最近版本摘要；
- `POST /api/admin/content?action=restore`：按版本 ID 恢复。

内容写入采用乐观并发控制：提交的 `expectedVersion` 与服务端当前版本不一致时返回 `409`，前端提示用户重新加载最新内容，不覆盖新版本。

每次保存先保存旧版本摘要或完整快照，再写当前版本。版本列表限制最近记录数量，防止 Blob 无限增长；被限制之外的版本不影响当前内容。

### 6.3 统计接口

现有 `POST /api/visit` 继续用于访客统计，并保留字段清洗、长度限制和不信任客户端标识的边界。现有 `GET /api/stats` 改为读取管理员会话；前端删除 `sessionStorage` 中保存后台 token 的逻辑。统计数据继续保存在独立的 `yyq-site-analytics` store。

### 6.4 跨域与公开内容

公开内容接口支持 Netlify 主站和 GitHub Pages 静态镜像读取，生产环境使用明确的允许来源，不使用任意来源通配符。后台管理请求只在 Netlify 主站执行。`VITE_ADMIN_SITE_URL` 或等价公开配置只用于 Pages 的跳转，不包含任何秘密。

## 7. 管理页面交互

### 7.1 登录页

- 邮箱和密码输入；
- 登录按钮；
- 首次初始化入口；
- 忘记密码入口；
- 登录失败、网络错误、服务未配置和会话过期提示。

### 7.2 后台首页

- 当前管理员邮箱；
- 退出登录；
- 总访问量、总访客数、今日访问量、当前在线人数；
- 最近访客列表；
- 六个栏目编辑入口；
- 最近内容更新时间；
- 最近修改记录。

### 7.3 编辑页

- 栏目导航；
- 当前栏目表单；
- 多行文本编辑；
- 列表项新增、删除、排序；
- 链接和日期字段；
- 保存、返回和恢复入口；
- 保存期间禁用重复提交；
- 保存成功显示“已发布”和更新时间。

### 7.4 错误与恢复

- 内容冲突返回 `409` 并保留当前输入；
- 网络失败不清空编辑中的表单；
- 未授权或会话过期时清理管理状态并回到登录页；
- 删除列表项和恢复历史版本必须二次确认；
- 公开接口失败时网站回退到代码内置默认内容，避免白屏。

## 8. 兼容与迁移

- 首次发布前由部署配置提供 `ADMIN_SETUP_TOKEN`；
- 初始化完成后可以移除或轮换 `ADMIN_SETUP_TOKEN`；
- 现有 `VISITOR_ADMIN_TOKEN` 不再被前端使用，统计接口切换到 Cookie 会话；
- 为避免现有公开页面在接口异常时失效，代码内保留当前静态内容作为默认回退；
- Netlify 主站读取动态内容；GitHub Pages 读取允许跨域的 Netlify 公开内容接口；
- 不把动态内容 Blob、账号信息和令牌提交到 GitHub 或 GitHub Pages。

## 9. 验证与发布标准

### 9.1 自动检查

- `npm test` 通过；
- `npm run typecheck` 通过；
- `npm run build` 通过；
- 新增认证、Cookie、输入校验、内容版本冲突、恢复令牌和接口契约测试；
- `git diff --check` 通过。

### 9.2 功能验收

- 未登录不能读取统计或修改接口；
- 初始化管理员只能成功一次；
- 错误密码不会泄露账号是否存在；
- 登录后可以读取统计数据；
- 六个栏目都能修改标题和正文；
- 项目、技能、简历列表支持新增、删除和排序；
- 保存后 Netlify 主站刷新显示新内容；
- GitHub Pages 公共页面能读取最新内容；
- GitHub Pages 的 `#admin` 能跳转到 Netlify 管理入口；
- 历史版本可以查看并恢复；
- 恢复令牌成功使用一次后不能再次使用；
- 退出登录后旧会话不能访问管理员接口；
- 统计数据仍能正常收集，访客端不需要管理员凭据。

### 9.3 部署验收

先创建 Netlify Draft Deploy，完成真实登录、保存、刷新、恢复和统计检查，再进行正式部署。发布时按网站维护规范同步版本、CHANGELOG 和操作文档，明确说明新增环境变量、Netlify 动态内容能力以及 GitHub Pages 只读镜像的限制。

## 10. 后续可选扩展

以下内容不属于本期实现，但当前设计为其保留了边界：

- 多管理员与角色权限；
- 邮件发送和邮件找回密码；
- 草稿、预览和正式发布分离；
- 图片上传和媒体资源管理；
- RAG 知识库的审核工作流；
- 更完整的访问趋势图和导出能力。
