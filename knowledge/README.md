# YYQ 公开知识库

这里存放个人网站问答助手可以使用的公开事实。`index.json` 是 Netlify `/api/ask` 的唯一事实来源，内容来自网站已经公开的个人经历、项目板和技能栏。

## 内容原则

- 只记录已经公开、可以由本人确认的事实。
- 不记录客户内部地址、账号、密钥、真实业务数据、未公开代码和私人联系方式。
- 银行项目只保留职责与测试方法概述，不记录客户名称、内部命令、日志原文、表结构、字段和个人金融信息。
- 不由助手返回手机号、邮箱、微信二维码、精确住址等联系资料；访客统一使用网站“联系我”入口。
- 项目状态必须区分“已完成”“进行中”“计划中”，不能把计划描述成成果。
- 具体资料尽量只描述一个项目或一个能力主题；宽泛问题通过顶层 `topics` 引用多条公开证据，原细粒度条目继续作为唯一事实来源。
- 总览条目的 `tags` 只放“技能概览、工具清单、技术栈”等高层主题，具体工具放在 `content`，避免抢占项目或单项能力问法。
- 更新事实时同时更新知识 `version` 与 `updatedAt`，运行 `npm run vectors:build`、`npm run evaluate:rag` 和 `npm test`。

## 字段

- `id`：稳定且唯一的资料 ID。
- `title`、`period`：展示给访客的来源名称和时间。
- `company`、`role`、`category`：检索元数据。
- `tags`、`aliases`：技术关键词、常见问法和同义表达。
- `content`：允许模型用于回答的公开事实。
- `visibility`：公开接口只加载 `public` 条目。
- `employmentPeriods`：可选的结构化任职月份，只用于可验证的时间线和从业跨度推导；与正文冲突时不进行推导。
- 顶层 `topics`：宽泛主题定义；`entryIds` 只能引用公开条目，`overviewEntryId` 指定优先展示的父级来源，`lexicalAnchors` 提供主题词法证据。

## 主题向量与事实推导

`npm run vectors:build` 会为每条公开知识和每个主题分别生成 512 维本地 BGE 向量，写入 schema v2 的 `vector-index.json`。宽泛主题按固定加法评分聚合最多 6 条配置证据；详细项目问法仍走条目级 RRF 和严格事实门控。

“事实推导”只读取已选公开条目和主题定义，支持时间计算、计数、分组、实体关联、比较和概括。每项推导都包含规则版本与来源条目 ID；输入缺失、时间线冲突或来源无法验证时省略结果，不让回答模型自行补全。

`index.json` 不接受来自网页访客的写入。任何内容变更都通过代码审查和重新部署发布。
